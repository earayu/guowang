# 取证式检索（三级检索 + 零命中证明）

## 为什么需要这份纪律

语义检索是**相关性截断**：返回 top-N 个最像的块，不保证穷尽。拿它去回答「有没有」，
会出现两种错误，且两种都很难被发现：

- **假阳性**：问「专家打分表」，语义检索返回「报价评分标准」，看着相关，其实答非所问。
- **假阴性**：库里确实有，但排序靠后没进 top-N，于是回答「没有」——这是最严重的一种，
  因为它是**言之凿凿的错**。

所以在动手检索之前，先决定这次要的是「找到相关材料」还是「证明存在/不存在」。两者用不同工具。

## 三级检索，各管一件事

| 层级 | 命令 | 能回答 | 不能回答 |
|---|---|---|---|
| 语义 | `apemind search QUERY --kb KB` | 哪些段落与问题相关 | 有没有、在第几行 |
| 精确 | `apemind grep PATTERN --kb KB` | 这个词在哪些行出现过、共几处 | 换了说法还成不成立 |
| 回读 | `apemind read HANDLE` | 这一行前后是什么、上下文够不够 | — |

规则：

1. **找材料用 search；下「有没有」的结论必须先做 grep。**
2. grep 支持 RE2 正则，中文字面量直接用；同一概念换 2~3 个同义写法各扫一次
   （如「投标保证金 / 保证金 / 担保」），只扫一个词就断言没有，风险很高。
3. grep 得到的 handle 是 `doc<id>@<version>#K`（块）或 `:<行号>`（单行）。
   **单行句柄回读只有一行**，看不出上下文——回读前把行号扩成区间（如 ±6/+10 行）。

## 零命中：必须区分「扫完了没有」

`grep` 返回的 `coverage` 字段决定你能说哪句话：

- `coverage = complete` → 扫描走完，可以说「库内共 0 处，没有」。
- `coverage` 不是 `complete`（如 `truncated_by_max_results`）→ 只说「本次未扫完，不能断定没有」，
  并给出现在扫了多少、被什么截断。

同理 `total_match_count`：

- 扫描完整时它是**准确总数**，可以说「共 N 处」。
- 返回条数被 `max-count` 截断时，只能说「展示前 N 条」，不能说「共 N 处」。

这两个概念经常被混成一句「找到 N 处」，客户一问「是不是全部」就露馅。

## 结论必须带检索范围

写「库里没有」时，后面必须跟三样东西，否则这句话不可信：

1. 查了哪些库（库名，不是库 ID）；
2. 用了哪些关键词 / 正则；
3. 扫描是否完整。

反例：「招标文件中未找到技术评分标准。」——没范围、没关键词、没说扫完没扫完。
正例：「在『国网湖北电力招标文件包 L1』（18 个标包）内，以『技术评分标准 / 技术评审细则 /
评分细则』扫全文，覆盖完整，0 处命中；同批次文件的对应章节为空段落。」

## 命中不等于答对

- 命中的是**同名不同标包**的文件时，必须报批次 + 标包号再引用。同名文件来自不同标包
  时不得合并成一份，也不得跨标包比较数字。
- 命中表格类内容时，注意 docx 转 markdown 后**合并单元格会在每行重复同一段文字**，
  按行计数会把 23 项数成 83 项。数条目要按「内容是否变化」判断边界。
- 命中后要回读原文再引用。摘录里的 `**`、`<u>` 是排版标记不是内容，引用时清掉，
  但不能改动文字本身。

## 表述分级（写答案时对照）

| 依据强度 | 什么情况 | 怎么表述 |
|---|---|---|
| A | 本项目原文，能回到文件 + 章节 + 行号 | 直接引用，标位置 |
| B | 本项目原文，但只能回到文件级 | 引用，注明未定位到行 |
| C | 通用范本 / 公开转述，非本项目原文 | 引用，**必须标「非本项目原文，须核对」** |
| 无 | 扫完 0 处，或覆盖不完整 | 分别说「没有」/「未扫完，不能断定」 |

C 级混进 A 级是本项目最容易出的合规问题：国网通用范本与项目招标文件长得很像，
连商务部分都可能逐字相同，但技术部分未必。来源等级必须显式标，不能默认升格。
