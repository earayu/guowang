## 三个必须主动交出去的短板

**一、这两格上一轮是灰的，是我们自己抓出来的解析错。**
模型对「签章是否加盖」会答三种话——「是（已加盖电子签章）」「通过」「是」，原来只认含「加盖」的，后两种被当成无法判定；签章名称有时带「（电子签章）」后缀，直接比字符串会把恩施误判成「签章主体与投标人不是同一人」。两处都改完后六家剧本 6/6 全对。
> 主动讲这个，比讲「全绿」可信得多：这些数是跑出来的，不是摆出来的。

**二、F4 的 20/20 与 8/8 是构造数据。**
行 32/39/46 的判据在"同标包其他投标人"身上，单份文件判不出来；六家真实数据法人各异、报价互不相同，用真实数据跑只会全过。所以那 8 个用例是为验证算子而构造的，不代表任何真实投标情形。

**三、抽取仍有抖动，所以不现场赌。**
同一版本重跑，襄阳 `seal_valid`、宜昌 `seal_name` 各偶发过一次没抽到。台上用落盘快照；客户要求实时重跑可以，但要先说清这条。

## 页面出问题时

1. 先用另一个浏览器打开同一个文件（Chrome / Edge 都行）。
2. 仍不行就只讲 W3，把 V7 的内容用嘴说（12 页签的读数在本手册第 5 节）。
3. 完全打不开时，`证据/国网Demo_W3v2_页面数据_6家8条.json` 里有全部 48 格的算式与原文，可以拿记事本打开照着念。
